# Clouvent Design

Applies Clouvent's approved visual identity to design decisions. Does not define the identity itself — reads it from source documents below.

## Must read

- `BRAND_SYSTEM.md` — exact colour tokens, typography scale, logo rules, graphic language, photography direction, UI/interaction language.
- `CLAUDE.md` → Brand & Design, Design Tokens — principle-level rules and the accessibility/motion tie-breaker.
- `PROJECT_BRIEF.md` — relevant page/business intent (audience, journey stage) for the thing being designed.

This skill must never override those documents. If they conflict, stop and report the conflict rather than choosing silently.

## Use for

New page design, section design, component visual direction, layout reviews, visual hierarchy decisions, brand-consistency reviews.

## Key checks

- Editorial craft × digital precision — typography and photography carry the design, not decoration.
- Image-first hierarchy with strong, intentional negative space.
- Restrained accent usage — copper per `BRAND_SYSTEM.md` §3, never flooded.
- Logo-derived graphic language only (`BRAND_SYSTEM.md` §6) — no unrelated motifs.
- Calm, intentional motion — no decorative animation.
- Mobile-first visual thinking, not a shrunk desktop layout.

## Avoid

- Generic SaaS card grids, gradients, or glassmorphism used as decoration.
- Arbitrary colours outside the approved token set.
- Unnecessary rounded containers or cards that don't improve information architecture.
- Random or excessive animation.
- Presenting invented or stock imagery as client work.
- Overusing copper as a full-surface or full-logo treatment.
- Poster-like/social-graphic layouts on the actual website.
- Reviving the legacy tagline "Infrastructure With Intelligence Built In." or locking a permanent tagline (see `BRAND_SYSTEM.md` §10).
